# ADR-0001. Разметка фрагментов парой закладок

## Контекст и постановка проблемы

Этап html2docx переносит фрагменты промежуточного HTML в шаблон DOCX по закладкам part_ и затем назначает стили Word по закладкам style_. Решение касается двух компонентов: преобразования xml2html, которое размечает фрагменты в HTML, и скрипта bookmarx.vbs, который читает эту разметку в Word.

До решения фрагмент размечался одним якорем, охватывающим содержимое: `<a name="part_…">…</a>`, `<a name="style_…">…</a>`. Word при открытии HTML превращает якорь, охватывающий блочные элементы, в закладку нулевой длины: начало фрагмента известно, конец — нет.

Из-за этого выявлены следующие проблемы. Скрипт брал конец фрагмента part_ по началу следующего якоря part_ и захватывал промежуток между якорями, отчего после вставленного текста появлялся лишний пробел. Якорь style_ абзаца охватывает один `<p>`, а якорь списка — весь `<ol>` или `<ul>`. По закладке нулевой длины стиль списка получает только первый пункт.

Вопрос: как размечать фрагмент, чтобы его границы однозначно определялись в Word для любых элементов?

## Движущие факторы решения

* Внутренность фрагмента копируется внутрь одноименной закладки; соседние фрагменты и промежутки между ними на границы не влияют.
* Одно правило разметки для всех закладок: part_ и style_, абзацев и списков.
* Границы фрагмента не зависят от того, как Word импортирует якоря, охватывающие блочные элементы.
* Разметка видна в HTML и понятна без чтения кода скрипта.
* Скрипт не разбирает HTML текстуально.

## Рассмотренные варианты

* Один якорь вокруг содержимого, конец по следующему якорю.
* Один якорь вокруг содержимого, служебный якорь конца вставляет скрипт.
* Один якорь вокруг содержимого, разный подход для абзацев и списков.
* Пара пустых якорей: открывающий и закрывающий.

## Результат решения

Выбран вариант «Пара пустых якорей», потому что только он удовлетворяет всем движущим факторам.

Любой фрагмент размечается парой пустых якорей, которые работают как открывающий и закрывающий теги:

```html
<a name="part_main"></a> … содержимое … <a name="close_part_main"></a>
```

Имя закрывающего якоря образуется приставкой `close_` к имени открывающего. Фрагмент — все, что находится между открывающей и закрывающей закладками. Правило едино для всех закладок без исключений; одиночные якоря и якоря, охватывающие содержимое, не применяются.

Закладки part_ в шаблоне DOCX остаются закладками-диапазонами: они задают зону замены, и закрывающая закладка в шаблоне не требуется.

### Последствия

* Хорошо, потому что фрагмент определяется только своей парой закладок и вставляется без лишних символов.
* Хорошо, потому что стиль списка назначается всем пунктам, а стиль абзаца — ровно абзацу, по одному и тому же правилу.
* Хорошо, потому что скрипт не разбирает HTML, а служебные якоря `pend_` упраздняются.
* Хорошо, потому что разметка явная и проверяется просмотром HTML.
* Плохо, потому что требуется доработать преобразование xml2html и скрипт bookmarx.vbs.
* Плохо, потому что после обработки скрипт должен удалять закладки `close_` из выходного документа.
* Плохо, потому что имя закрывающей закладки на 6 символов длиннее открывающей, а Word ограничивает имя закладки 40 символами. Имена style_ содержат закодированное имя стиля и хвост уникальности, поэтому для длинных имен стилей ограничение может быть превышено.

### Подтверждение

Реализация соответствует решению, если выполнены следующие критерии.

* В HTML для каждого пустого якоря `X` с префиксом part_ или style_ есть ровно один пустой якорь `close_X`, расположенный после него.
* В HTML нет якорей part_ и style_, охватывающих содержимое.
* Имена всех якорей, включая закрывающие, не длиннее 40 символов.
* Скрипт bookmarx.vbs определяет фрагмент только по паре закладок `X` и `close_X`; в коде нет вычисления границ по соседним закладкам и текстового разбора HTML.
* В выходном DOCX после текста, вставленного в закладку part_, нет символов, отсутствующих во фрагменте HTML.
* Стиль списка назначен каждому пункту списка.
* В выходном DOCX нет закладок с префиксами `close_` и `pend_`.
* Журнал скрипта не содержит предупреждений о пустых фрагментах и пропущенных стилях на эталонном документе.

## Плюсы и минусы вариантов

### Один якорь вокруг содержимого, конец по следующему якорю

`<a name="part_X">…</a>`; конец фрагмента — начало следующей закладки part_ или конец документа.

* Хорошо, потому что не требует изменений в HTML.
* Плохо, потому что в фрагмент попадает промежуток между якорями — лишний пробел после вставленного текста.
* Плохо, потому что границы фрагмента зависят от соседних фрагментов.
* Плохо, потому что неприменим к style_: якоря стилей вложены и не следуют подряд.

### Один якорь вокруг содержимого, служебный якорь конца вставляет скрипт

Скрипт находит в копии HTML парный `</a>` и вставляет перед ним `<a name="pend_X"></a>`.

* Хорошо, потому что границы определяются по самому якорю, лишнего пробела нет.
* Хорошо, потому что не требует изменений в преобразовании xml2html.
* Плохо, потому что скрипт разбирает HTML текстуально.
* Плохо, потому что механизм не виден в разметке и непонятен без чтения кода скрипта.

### Один якорь вокруг содержимого, разный подход для абзацев и списков

Для абзаца достаточно начала закладки, для списка конец определяется отдельно.

* Хорошо, потому что для абзацев ничего не меняется.
* Плохо, потому что разные правила для разных элементов ведут к беспорядку в разметке и в коде.

### Пара пустых якорей

`<a name="X"></a> … <a name="close_X"></a>`.

* Хорошо, потому что одно правило для всех закладок.
* Хорошо, потому что границы не зависят ни от соседей, ни от импорта якорей в Word.
* Нейтрально, потому что закрывающие закладки нужно удалять из результата.
* Плохо, потому что удлиняет имена закладок на 6 символов.

## Дополнительная информация

Описание реализации этапа — документ bookmarx-vstavka-po-zakladkam-part.md; его требуется привести в соответствие с этим решением. Решение пересматривается, если Word начнет иначе импортировать пустые якоря или если ограничение длины имени закладки станет препятствием для имен style_.

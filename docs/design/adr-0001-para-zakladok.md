# ADR-0001. Разметка фрагментов парой закладок

## Контекст и постановка проблемы

Этап html2docx переносит фрагменты промежуточного HTML в шаблон DOCX по закладкам part_ и затем назначает стили Word по закладкам style_. Решение касается двух компонентов: преобразования xml2html, которое размечает фрагменты в HTML, и скрипта bookmarx.vbs, который читает эту разметку в Word.

До решения фрагмент размечался одним якорем, охватывающим содержимое: `<a name="part_…">…</a>`, `<a name="style_…">…</a>`. Word при открытии HTML превращает якорь, охватывающий блочные элементы, в закладку нулевой длины: начало фрагмента известно, конец — нет.

Из-за этого выявлены следующие проблемы. Скрипт брал конец фрагмента part_ по началу следующего якоря part_ и захватывал промежуток между якорями, отчего после вставленного текста появлялся лишний пробел. Якорь style_ абзаца охватывает один `<p>`, а якорь списка — весь `<ol>` или `<ul>`. По закладке нулевой длины стиль списка получает только первый пункт.

Вопрос: как размечать фрагмент, чтобы его границы однозначно определялись в Word для любых элементов?

## Движущие факторы решения

* Скрипт копирует внутренность фрагмента в закладку шаблона, которую задаёт подпись открывающего якоря; соседние фрагменты и промежутки между ними на границы не влияют.
* Одно правило разметки для всех закладок: part_ и style_, абзацев и списков.
* Границы фрагмента не зависят от того, как Word импортирует якоря, охватывающие блочные элементы.
* Разметка видна в HTML и понятна без чтения кода скрипта.
* Скрипт не разбирает HTML текстуально.

## Рассмотренные варианты

* Один якорь вокруг содержимого, конец по следующему якорю.
* Один якорь вокруг содержимого, разный подход для абзацев и списков.
* Пара якорей: открывающий и закрывающий, с подписью внутри каждого.

## Результат решения

Выбран вариант «Пара якорей с подписью», потому что только он удовлетворяет всем движущим факторам.

Любой фрагмент размечается парой якорей, которые работают как открывающий и закрывающий теги. Внутри каждого якоря стоит одна и та же служебная подпись: осмысленный текст, по которому скрипт связывает разметку с шаблоном или со стилем Word. Атрибут `name` задаёт только тип закладки и хвост уникальности; форма хвоста не регламентируется.

Пример зоны вставки:

```html
<a name="part_i737262">main</a> … содержимое … <a name="_part_i737262">main</a>
```

Пример элемента со стилем:

```html
<a name="style_i837364">Обычный козел</a> … содержимое … <a name="_style_i837364">Обычный козел</a>
```

Имя закрывающего якоря образуется приставкой `_` к полному имени открывающего. Фрагмент — все, что находится между открывающей и закрывающей закладками. Правило едино для всех закладок без исключений; одиночные якоря и якоря, охватывающие содержимое, не применяются.

Подпись внутри якоря нужна, чтобы Word при импорте HTML создал закладку ненулевой длины. Закладку нулевой длины Word не переносит, если она стоит на границе копируемого диапазона; такие границы возникают у каждой зоны и у каждого элемента со стилем.

Связь с шаблоном для part_: в DOCX закладка зоны называется `part_` и далее подпись без изменений, например `part_main`. Скрипт находит в HTML пару `part_…` / `_part_…`, читает подпись открывающего якоря (`main`) и вставляет содержимое между парой в эту закладку. В одном HTML не бывает двух пар part_ с одинаковой подписью.

Связь со стилем Word для style_: имя стиля берётся только из подписи открывающего якоря. Подпись может быть на любом языке и содержать любые символы; кодирования имени стиля в атрибуте `name` нет. Скрипт назначает стиль, имя которого в шаблоне совпадает с подписью.

После вставки зон и назначения стилей скрипт удаляет подписи из закладок якорей HTML в выходном DOCX. Скрипт очищает диапазон каждой такой закладки по её имени и не сравнивает текст подписи с эталонной строкой. Закладки зон шаблона `part_<подпись>` скрипт не очищает: после вставки они охватывают всё содержимое зоны.

Закладки part_ в шаблоне DOCX остаются закладками-диапазонами: они задают зону замены, и закрывающая закладка в шаблоне не требуется.

### Последствия

* Хорошо, потому что фрагмент определяется только своей парой закладок и вставляется без лишних символов.
* Хорошо, потому что стиль списка назначается всем пунктам, а стиль абзаца — ровно абзацу, по одному и тому же правилу.
* Хорошо, потому что разметка явная и проверяется просмотром HTML.
* Хорошо, потому что имя стиля читается из подписи якоря, а не из закодированного имени закладки.
* Плохо, потому что требуется доработать преобразование xml2html и скрипт bookmarx.vbs.
* Плохо, потому что Word считает закладки, имя которых начинается с `_`, скрытыми и не включает их в коллекцию закладок документа, пока у коллекции не установлено свойство ShowHidden. Скрипт должен устанавливать его перед поиском закрывающих закладок.
* Нейтрально, потому что имя закрывающей закладки на 1 символ длиннее открывающей, а Word ограничивает имя закладки 40 символами. Хвост уникальности в `name` нужно подбирать так, чтобы уложиться в лимит.

### Подтверждение

Реализация соответствует решению, если выполнены следующие критерии.

* В HTML для каждого открывающего якоря `X` с префиксом part_ или style_ есть ровно один закрывающий якорь `_X`, расположенный после него; подписи в паре совпадают.
* В HTML нет якорей part_ и style_, охватывающих содержимое.
* Имена всех якорей, включая закрывающие, не длиннее 40 символов.
* Скрипт bookmarx.vbs определяет фрагмент только по паре закладок `X` и `_X`; в коде нет вычисления границ по соседним закладкам и текстового разбора HTML.
* Скрипт сопоставляет закладку шаблона `part_<подпись>` с парой HTML по подписи открывающего якоря part_.
* Скрипт назначает стиль по подписи открывающего якоря style_, без декодирования из `name`, и не назначает стиль заголовка абзацам-подписям якорей.
* Скрипт удаляет подписи, очищая диапазон закладки якоря HTML по имени закладки; закладки зон шаблона `part_<подпись>` не очищает.
* В выходном DOCX после текста, вставленного в закладку part_, нет символов, отсутствующих во фрагменте HTML, и нет служебных подписей якорей.
* Стиль списка назначен каждому пункту списка.
* Журнал скрипта не содержит предупреждений о пустых фрагментах и пропущенных стилях на эталонном документе.

## Плюсы и минусы вариантов

### Один якорь вокруг содержимого, конец по следующему якорю

`<a name="part_X">…</a>`; конец фрагмента — начало следующей закладки part_ или конец документа.

* Хорошо, потому что не требует изменений в HTML.
* Плохо, потому что в фрагмент попадает промежуток между якорями — лишний пробел после вставленного текста.
* Плохо, потому что границы фрагмента зависят от соседних фрагментов.
* Плохо, потому что неприменим к style_: якоря стилей вложены и не следуют подряд.

### Один якорь вокруг содержимого, разный подход для абзацев и списков

Для абзаца достаточно начала закладки, для списка конец определяется отдельно.

* Хорошо, потому что для абзацев ничего не меняется.
* Плохо, потому что разные правила для разных элементов ведут к беспорядку в разметке и в коде.

### Пара якорей с подписью

`<a name="part_<хвост>">подпись</a> … <a name="_part_<хвост>">подпись</a>`; для style_ — тот же принцип с префиксом style_.

* Хорошо, потому что одно правило для всех закладок.
* Хорошо, потому что границы не зависят ни от соседей, ни от импорта якорей в Word.
* Хорошо, потому что подпись задаёт связь с шаблоном и имя стиля без кодирования в `name`.
* Нейтрально, потому что удлиняет имена закладок на 1 символ у закрывающей пары.
* Плохо, потому что закрывающие закладки в Word скрытые и требуют ShowHidden.

## Дополнительная информация

Описание реализации этапа — документ bookmarx-vstavka-po-zakladkam-part.md. Решение пересматривается, если Word начнет иначе импортировать якоря с текстом внутри или если ограничение длины имени закладки станет препятствием.

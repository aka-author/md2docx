# Перенос HTML в документ Word по закладкам part_

## Назначение документа

Документ описывает реализацию этапа html2docx, выполняемого скриптом bookmarx.vbs. Этап переносит промежуточный HTML в документ Word не одним блоком на все тело, а отдельными фрагментами. Каждый фрагмент связан с закладкой Word, имя которой начинается с префикса part_. Такой перенос сохраняет в выходном DOCX все участки шаблона вне закладок part_ и заменяет только те диапазоны, для которых в HTML есть одноименный якорь. После переноса выполняется второй проход, назначающий стили Word по закладкам с префиксом style_.

Помимо принципа работы документ фиксирует проблемы, выявленные при отладке, и принятые решения. Эта часть важна для сопровождения: большинство отказов на данном этапе вызвано не логикой разметки, а поведением Word при автоматизации через COM.

## Место этапа в конвейере

На вход bookmarx.vbs поступает HTML с якорями name. Якоря с префиксом part_ задают крупные зоны вставки в шаблон DOCX. Якоря с префиксом style_ размечают элементы внутри этих зон для последующего применения имен стилей Word. Способ получения HTML этап не регламентирует. Перечень имен part_ и состав зон согласуют автор HTML и автор шаблона Word; скрипт не проверяет смысл разделов.

Предыдущая версия скрипта очищала основной текст шаблона и вставляла HTML целиком, из-за чего терялось содержимое шаблона вне вставки. Текущая версия выполняет точечную замену только по закладкам part_.

## Термины

**HTML** — файл первого аргумента bookmarx.vbs.

**Входной DOCX** — файл второго аргумента: шаблон Word с закладками part_.

**Выходной DOCX** — файл третьего аргумента, получаемый после замены содержимого зон part_.

**Якорь part_** — элемент HTML с атрибутом name, значение которого начинается с part_.

**Закладка part_** — закладка в DOCX с тем же именем, что у якоря part_. Диапазон закладки — область замены.

**Зона вставки** — диапазон закладки part_ во входном DOCX.

**Исходный фрагмент** — область импортированного в Word HTML, соответствующая одноименному якорю part_.

**Якорь style_** — элемент HTML с атрибутом name, значение которого начинается с style_. Он размечает элемент внутри зоны part_ и после переноса становится закладкой Word.

**Закладка style_** — закладка в выходном документе, имя которой начинается с style_ и кодирует имя стиля Word.

## Интерфейс скрипта

Скрипт запускается интерпретатором cscript и принимает три обязательных аргумента и один необязательный.

| Аргумент | Назначение |
|---|---|
| 1 | Путь к HTML |
| 2 | Путь ко входному DOCX, то есть к шаблону |
| 3 | Путь к выходному DOCX |
| 4 | Путь к файлу журнала; при отсутствии журнал создается рядом с HTML с именем вида `<имя>.bookmarx.log` |

Относительные пути приводятся к абсолютным относительно текущего каталога. Проверка выполняется по наличию двоеточия или ведущей обратной косой черты, а не по существованию файла, поскольку выходной файл и файл журнала на момент разбора аргументов еще не созданы.

## Общий порядок работы

Скрипт открывает журнал до обращения к Word, затем проверяет наличие входных файлов, создает экземпляр Word, открывает копии шаблона и HTML, выполняет замену по зонам part_, закрывает импортированный HTML, назначает стили по закладкам style_, сохраняет результат и завершает Word. Копии во временном каталоге удаляются в самом конце.

Порядок шагов выбран так, чтобы журнал содержал запись о каждом потенциально блокирующем действии до его выполнения. Если работа останавливается, последняя строка журнала указывает на точку остановки.

## Определение зон вставки в шаблоне

Скрипт перебирает закладки открытого шаблона и отбирает те, чье имя начинается с part_. Для каждой отобранной закладки запоминаются имя и начальная позиция диапазона, после чего список сортируется по убыванию начальной позиции.

Обратный порядок обработки принципиален. Вставка изменяет длину документа, поэтому позиции закладок, расположенных после измененной зоны, смещаются. При обработке от конца документа к началу позиции еще не обработанных зон остаются действительными.

## Определение границ исходного фрагмента

HTML открывается в Word как документ, а не разбирается текстуально. Word при импорте превращает якорь `<a name="…">` в закладку, но эта закладка получается **пустой**: она отмечает точку, а не диапазон содержимого. Поэтому границы исходного фрагмента вычисляются так:

начало фрагмента — начало закладки part_ в импортированном HTML; конец фрагмента — начало следующей по тексту закладки part_, а для последней зоны — конец документа.

Такое правило опирается на то, что зоны part_ в HTML идут последовательно и не вложены друг в друга. Если фрагмент получается пустым, зона пропускается с предупреждением в журнале.

## Замена содержимого зоны

Для каждой зоны скрипт присваивает свойству FormattedText диапазона закладки в шаблоне значение свойства FormattedText вычисленного диапазона импортированного HTML. Одно присваивание заменяет прежнее содержимое зоны новым вместе с оформлением и вложенными закладками.

Присваивание FormattedText не зависит ни от буфера обмена, ни от выделения. Работа через Selection на этом этапе не применяется: Selection относится к активному окну, а Word запускается невидимым.

Если присваивание завершается ошибкой Word, ошибка записывается в журнал, зона пропускается, и обработка продолжается со следующей зоны.

## Имена закладок style_

Полное имя закладки состоит из префикса `style_`, закодированного имени стиля Word и незначимого хвоста. Хвост отделяется последним символом подчеркивания в строке; он нужен только для уникальности имен закладок в пределах документа и в имя стиля не входит.

При кодировании имени стиля каждый пробел заменяется на `_s`, каждое подчеркивание — на `__`. Так стиль `Heading 1` дает середину `Heading_s1`, а вместе с хвостом `d1e15` получается имя `style_Heading_s1_d1e15`.

При декодировании сначала снимается префикс `style_`, затем отбрасывается все после последнего символа подчеркивания, в оставшейся строке `__` заменяется на `_`, а `_s` — на пробел. Результат должен совпадать с именем стиля в шаблоне.

## Применение стилей по закладкам style_

Проход выполняется после переноса всех зон part_ и до сохранения, в том же открытом документе. Скрипт собирает имена закладок основного текста, подходящих под правило имени style_, и обрабатывает собранный список. Список формируется заранее, а не по ходу обхода коллекции, поскольку назначение стилей изменяет документ.

Для каждой закладки имя декодируется, стиль ищется в документе по полученному имени. Абзацный стиль назначается каждому абзацу диапазона закладки, символьный — диапазону целиком. Если стиля с таким именем в документе нет или тип стиля не поддерживается, закладка пропускается с предупреждением, и проход продолжается.

Механизмы part_ и style_ независимы: part_ определяет зону замены, style_ задает оформление элементов внутри перенесенного содержимого.

## Сохранение результата

Выходной файл сохраняется методом SaveAs2 в формате wdFormatXMLDocument. Сохранение выполняется **в любом случае**, независимо от того, удалась ли замена всех зон и назначение всех стилей. Это требование к поведению скрипта: отсутствие выходного файла недопустимо даже при ошибках на отдельных зонах, поскольку по результату нужно видеть, что именно получилось.

## Журнал

Каждая запись журнала одновременно выводится на экран и дописывается в файл. Файл открывается и закрывается на каждой записи, без буферизации. Это сделано намеренно: при аварийном завершении процесса буферизованный журнал терял последние строки, то есть именно ту часть, которая указывает на причину отказа.

В журнал попадают: разобранные пути, размеры входных файлов, создание объекта Word и его версия, каждое открытие документа с указанием пути и режима, перечень найденных закладок part_ с их позициями, порядок обработки, вычисленные границы источника и приемника для каждой зоны, результат замены, число найденных закладок style_ вместе с числом назначенных и пропущенных стилей, факт сохранения и завершение Word.

## Проблемы, которые пришлось решать

### Модальный диалог Word о ранее аварийном файле

После того как Word однажды завершился аварийно с открытым шаблоном, он занес путь шаблона в список отключенных документов в разделе реестра `HKCU\Software\Microsoft\Office\16.0\Word\Resiliency\DisabledItems`. При каждом следующем открытии Word показывал окно с вопросом, открывать ли файл, который «caused a serious error».

При автоматизации через COM это означает полную остановку: Word невидим, окно показать некому, а вызов Documents.Open не возвращает управление. Свойство DisplayAlerts такой диалог не подавляет, поскольку он относится не к предупреждениям, а к механизму устойчивости Word.

Решение состоит из двух частей. Разовая часть — очистка раздела DisabledItems и завершение оставшихся процессов Word. Постоянная часть — открытие не исходных файлов, а их копий во временном каталоге: путь копии каждый раз новый для механизма устойчивости, поэтому прежние отметки на него не распространяются.

### Пустые закладки part_ в импортированном HTML

Первая реализация копировала содержимое прямо по закладке импортированного HTML. Это приводило к ошибке Word «This method or property is not available because no text is selected», скрипт прерывался, выходной файл не создавался.

Причина в том, что Word при импорте HTML превращает якорь в закладку нулевой длины. Копировать по такой закладке нечего. Решение описано выше: границы фрагмента вычисляются по соседним закладкам part_, а не берутся из диапазона самой закладки.

### Распознавание имен закладок style_

В прежней версии скрипта принадлежность закладки к механизму style_ определялась регулярным выражением, которое требовало, чтобы хвост имени состоял только из цифр. Преобразование xml2html формирует хвосты вида `d1e15`, и под это условие они не подходили. В результате проход находил нулевое число закладок и молча завершался, не назначив ни одного стиля.

Правило заменено на проверку префикса и наличия разделителя хвоста, без требований к составу символов хвоста.

### Прерывание скрипта до сохранения

Любая ошибка Word в ходе вставки останавливала интерпретатор, и шаг сохранения не выполнялся. Внешне это выглядело как отсутствие результата без объяснений, а в памяти оставался процесс Word с открытыми документами.

Теперь обработка каждой зоны изолирована: ошибка фиксируется в журнале и не прерывает цикл. Дополнительно весь этап вставки обернут обработчиком, после которого сохранение выполняется в любом случае.

### Остановка на прерывании вместо продолжения

В промежуточной версии при неудаче скрипт вызывал завершение процесса прямо из вложенных процедур, когда документы Word были открыты. Процесс cscript завершался, а Word оставался в памяти с незакрытыми документами. Накопление таких процессов и приводило к аварийным завершениям, из-за которых шаблон попадал в список отключенных документов. Прерывание из середины работы сохранено только для случаев, когда Word еще не создан: отсутствие аргументов и отсутствие входных файлов.

### Подмена переменной tmp в конфигурации

Файл cfg.bat выполняет `set tmp=%root%\tmp`. Эта команда переопределяет не только переменную конвейера, но и стандартную переменную окружения TMP для всех дочерних процессов. В результате временный каталог, который возвращает система, указывает на рабочий каталог проекта.

Следствие наблюдалось непосредственно: при запуске через конвейер копии для Word создавались в `sample\tmp`, а при прямом запуске того же скрипта из командной строки — в пользовательском временном каталоге. Этим же объясняется появление в `sample\tmp` посторонних файлов, которые никто из скриптов конвейера не создает: журнала запуска Java, диагностических файлов Word и файлов кэша с именами вида `prep_*_V8_perf.cache`. Все это пишут Java и Word в то место, которое для них назначено как временный каталог.

### Формирование пути выходного каталога

В md2docx.bat путь выходного каталога формировался конструкцией `%~dp3`, которая возвращает каталог аргумента, разбирая аргумент как путь к файлу. Для аргумента, который сам является каталогом, результатом оказывался родительский каталог, и выходной документ сохранялся на уровень выше ожидаемого. Используется прямое значение аргумента с добавлением разделителя.

### Незавершенные процессы Word

После вызова Quit процесс Word не всегда исчезает сразу. Вопрос остается открытым: если процесс переживает завершение скрипта, следующий запуск работает с уже существующим экземпляром Word, что ранее приводило к описанным выше отказам. При сопровождении имеет смысл контролировать наличие процессов WINWORD после прогона.

## Границы текущей реализации

Скрипт выполняет перенос по закладкам part_ и назначение стилей по закладкам style_. Построение оглавления на этом этапе не выполняется: прежний механизм опирался на текстовый маркер в шаблоне и из схемы исключен.
